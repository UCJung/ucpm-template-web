# 기능정의서 작성 지침

병원운영 경영지표 분석 화면의 기능정의서(Markdown) 작성 규칙. 신규 화면 추가 시 본 지침을 그대로 적용한다.

---

## 1. 문서 성격

| 항목 | 내용 |
|---|---|
| 형식 | Markdown |
| 역할 | 화면·컴포넌트 단위 기능 정의. 개발 착수 기준 문서 |
| 대상 독자 | 개발자, 기획 검토자 |
| 동기화 방향 | 본 문서 → 화면설계서(프로토타입). 역방향 반영 금지 |

프로토타입에만 존재하는 구현 세부(내부 상태 변수, 목업 데이터 등)는 본 문서에 기재하지 않는다.

---

## 2. Index 표기 규칙

계층 구조를 기호로 구분한다. 숫자 나열(`6-2-1-2`) 방식은 사용하지 않는다.

| 기호 | 계층 | 대상 |
|---|---|---|
| `1.` | 1depth | 화면 구성 영역 (GNB / 상단바 / 요약 패널 / 본문 패널) |
| `1)` | 2depth | 영역 내 컴포넌트 (필터바 / 드릴다운 영역 / 좌·우측) |
| `(1)` | 3depth | 컴포넌트 내 엘리먼트 (드롭다운 / 목록 / 차트) |
| `①` | 4depth | 엘리먼트의 항목·컬럼 |

**적용 원칙**
- 컴포넌트 정의 제목은 경로 전체를 노출한다 — `4. 본문 패널 › 2) 드릴다운 › (1) 좌열 · 진료과 목록`
- 화면에 존재하지 않는 컴포넌트는 번호를 남기지 않는다. 컴포넌트 삭제 시 후속 번호를 전부 재정리한다
- 상태·오류 표에서 Index를 참조할 때는 S01/S02 구분자를 함께 표기한다
- 컴포넌트 간 연동을 설명할 때는 Index 나열 대신 **컴포넌트 이름**을 쓴다
  - (X) `(2)·2)-(1)·2)-(2) 갱신`
  - (O) `선택날짜기준 현황 패널·일자별 지연현황 차트·일자별 예약율현황 차트 갱신`

## 3. 섹션 구성

| 순서 | 섹션 | 내용 |
|---|---|---|
| 목차 | 목차 | 섹션 번호·제목·간략설명 |
| 1 | 화면 목록 | 화면ID와 화면명 |
| 2 | Index 표기 규칙 | 계층별 기호 체계 |
| 3~n | 화면별 정의 | 화면 설명 → 구조도 → 컴포넌트 및 엘리먼트 |
| n+1 | 화면 상태값 · 전이 | 화면 단위 상태와 전이 조건 |
| n+2 | 상태별 표시 정의 | Default·Hover·Selected·Disabled·Error |
| n+3 | 오류·예외 메시지 | 상황별 표시 문구 |
| n+4 | 로딩 표시 정의 | 스켈레톤 방식 상세 |
| n+5 | 협의 필요 사항 | 미확정 항목 |
| 말미 | 참조 파일 / 문서 갱신 이력 | |

**중복 금지** — 컴포넌트 정의에 기재한 기본값·선택값을 별도 "확정 사항" 표로 다시 모으지 않는다.

## 4. 화면별 정의

### 4.1 화면 설명
50자 이내 한 줄. 화면의 목적만 기술한다.

### 4.2 구조도
Mermaid `flowchart TD`로 작성한다.
- 노드 라벨에 Index와 컴포넌트명을 함께 넣는다 — `"4. 본문 패널"`, `"(1) 좌열 · 진료과 목록"`
- 연동 관계는 점선 화살표로 표기한다 — `D1 -. 선택 시 갱신 .-> D2`
- 화면에서 삭제한 컴포넌트의 노드는 즉시 제거한다

### 4.3 컴포넌트 및 엘리먼트
컴포넌트 단위로 소제목을 세우고 아래에 항목을 나열한다.

**기술 순서**
1. `기본값` — 입력 컨트롤에만 사용
2. `선택값` — 드롭다운·토글의 가능한 값 (기본값 표시)
3. 산출·검증 규칙 — 계산식, 유효성 조건, 조회 범위, 임계값
4. `onLoad` — 화면 진입 시 동작 (목록·차트·달력)
5. 엘리먼트별 이벤트 — `onClick` / `onChange` / `onHover` / `onMouseLeave`
6. `항목` 표 — Index · 항목명 · 설명

**용어 사용 원칙**
- `기본값`과 `onLoad`를 혼용하지 않는다. 컨트롤의 초기값은 `기본값`, 화면의 진입 동작은 `onLoad`
- 목록·차트에는 `기본 선택` 대신 `onLoad : … 첫 번째 항목 자동 선택`으로 쓴다

**작성 예**
```
**4. 본문 패널 › 1) 필터바 › (1) 집계기간 (드롭다운)**
- 기본값 : `월간`
- 선택값 : `월간` / `주간` / `직접지정`
- 기간 산출 규칙 (롤링 기준)
  | 선택값 | 산출 기간 |
  |---|---|
  | 월간 | 현재일 − 1개월 ~ 현재일 |
  | 주간 | 현재일 − 7일 ~ 현재일 |
- onChange : 롤링 기준으로 조회기간 자동 갱신 및 재조회
```

## 5. 문체 규칙

| 규칙 | 예시 |
|---|---|
| 명사형 종결 | `조회기간 기준 재조회` (O) / `재조회한다` (X) |
| 서술형 종결 금지 | `~이다`, `~한다`, `~합니다` 사용 금지 |
| 직관적 표현 | 모호한 수식어 없이 동작·조건만 기술 |
| 값·코드는 백틱 | `월간`, `#57B0A0`, `22영업일`, `FAIL` |
| 표시 문구는 백틱 + 마침표 | `해당 조건의 진료과가 없습니다.` |
| 이벤트명은 원문 | `onLoad`, `onClick`, `onChange`, `onHover` |
| 날짜 형식은 한글 | `월/일`, `월/일(요일)` — `M/D` 표기 금지 |

## 6. 화면 상태값 · 전이

화면 단위로 상태를 정의한다. 컴포넌트별 개별 상태는 두지 않는다.

표 구성: `상태 | 진입 조건 | 화면 표시 | 전이`

- 상태 코드는 영문 대문자 — `INIT` / `SELECTED` / `EMPTY` / `INVALID` / `ERROR`
- 화면 진입 시 항상 `INIT`부터 시작한다 (필터·선택 상태 미유지)
- 상태 전이 시 갱신 대상은 구조도의 연동 관계에 정의된 컴포넌트로 한정한다
- **실제로 발생하지 않는 상태는 정의하지 않는다.** 정의 전 발생 가능성을 반드시 검토한다
  - 예: 선택값이 항상 유지되는 달력에는 `UNSELECTED` 상태 미존재
  - 예: 목록과 하위 목록이 동일 조건으로 필터되면 하위 0건 상태 미존재

---

## 7. 상태별 표시 정의

표 구성: `Index | 항목 | 상태 | 표시`

- **해당 상태가 실제로 발생하는 항목만 정의한다.** 전 항목에 Default~Error를 일괄 부여하지 않는다
- 미기재 상태는 해당 항목에 존재하지 않음을 의미한다
- 섹션 말미에 상태별 적용 범위를 명시한다
  - `Error : 조회기간 입력에만 존재`
  - `Disabled : 달력 날짜 셀에만 존재`
  - `Selected : 단일 선택 컴포넌트(목록 행·날짜 셀·차트 막대)에만 존재`

---

## 8. 오류·예외 메시지

표 구성: `Index | 항목 | 상황 | 표시 문구`

- 발생 가능한 항목만 정의한다
- 문구는 실제 화면에 노출되는 완성 문장으로 쓴다
- 공통 규칙을 섹션 말미에 명시한다
  - 빈 상태·오류 상태에서도 컴포넌트 영역과 레이아웃을 유지한다. 영역 자체를 숨기지 않는다
  - 값 없음은 `-`로 표기한다. `0` 대입·직전값 보간을 금지한다
  - 조회 실패 영역만 오류를 표시하고 다른 영역은 기존 값을 유지한다
  - 유효성 오류는 입력 컨트롤 하단에 표시하고 조회를 실행하지 않는다

---

## 9. 로딩 표시 정의

전 화면 공통 **스켈레톤** 방식. 스피너·기존값 유지 방식 사용 금지.

| 대상 | 표시 방식 |
|---|---|
| 요약 카드 | 항목명 유지, 수치 자리에 회색 막대 |
| 목록 | 헤더 유지, 본문 행을 회색 막대로 대치 |
| 차트 | 축·임계선 유지, 막대·선 자리에 회색 블록 |
| 달력 | 그리드 구조 유지, 셀 배경을 회색으로 |

필터 컨트롤은 스켈레톤 대상이 아니다. 로딩 중에도 상시 조작 가능하다.

---

## 10. 작성 절차

1. 화면 목록 확정 — 화면ID·화면명
2. 화면별 컴포넌트 구조도 작성 — Index 부여
3. 컴포넌트별 기본값·선택값·산출 규칙·이벤트·항목 정의
4. 화면 상태값·전이 도출 — 발생 가능성 검토 후 실재 상태만 정의
5. 상태별 표시·오류 문구·로딩 표시 정의
6. 미확정 항목을 협의 필요 사항에 기록

---

## 11. 점검 항목

- [ ] Index가 화면에 실재하는 컴포넌트와 1:1 대응하는가
- [ ] 삭제한 컴포넌트의 Index·구조도 노드·참조가 모두 제거되었는가
- [ ] `기본값`과 `onLoad`가 혼용되지 않았는가
- [ ] 정의한 상태가 실제로 발생 가능한가
- [ ] 동일 내용을 두 섹션에 중복 기재하지 않았는가
- [ ] 서술형 종결이 남아 있지 않은가
- [ ] Index 나열로 컴포넌트를 지칭한 문장이 없는가
