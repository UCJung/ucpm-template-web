- **설명**: 사람과 AI가 협업해 요구사항정의서를 점진적으로 구체화하는 절차·역할·작성 규칙 정의

- **수정일**: 2026-09-03

확정하는 공통 기준 제공.

## §1 목적·적용 대상

- **목적**: 요구사항 분석 단계에서 사람·AI가 같은 절차·역할·규칙으로 협업, 요구사항정의서 산출.
- **적용 대상**: 요구를 제시·검토·승인하는 **사람**, 초안 작성·구체화를 수행하는 **AI**.
- **산출물**: 요구사항정의서(`docs/[요구분석]_요구사항정의서.md` 양식).

---

## §2 기본 원칙

가이드 전반을 관통하는 기조.

| 원칙 | 내용 |
|---|---|
| **What만 정의** | 요구(무엇을)만 기술. 화면설계·입력/처리/출력·아키텍처·DB·기술선택 등 How는 IA·설계 단계 산출로 제외 |
| **점진적 구체화** | 최소 시드(필요성·배경·핵심 기능)에서 시작, 회차를 나눠 구체화. 1회 완성·확정 지양 |
| **임의 확정 금지** | 자료 부족·추론 필요 지점은 임의로 채우지 않음. **권장안 + 예시**로 사람에게 의사결정 요청 |
| **의사결정 기반 진행** | 사람의 결정·지시를 받아 반영. 불가피한 임시값은 `(가정)` 표기 |
| **검증 가능성** | 인수조건(AC)은 측정·판정 가능한 형태로 기술 |

## §3 협업 절차

사람의 초기 Need를 요구사항정의서로 수렴하는 반복 절차.

```mermaid
flowchart LR
    N["① Need 제공(사람)<br/>필요성·배경·핵심 기능"] --> D["② 초안 작성(AI)<br/>양식 구조로 채움"]
    D --> Q["③ 의사결정 요청(AI)<br/>권장안·예시 + 질문"]
    Q --> C["④ 결정·수정(사람)"]
    C --> R["⑤ 구체화 반영(AI)"]
    R --> G{"⑥ 검토·승인(사람)"}
    G -->|"보완 필요"| Q
    G -->|"확정"| F["요구사항정의서 확정"]
```

- 각 회차는 **초안/구체화 + 의사결정 요청**으로 구성, 사람 결정 후 다음 회차 진행.
- 승인 전까지 AI는 산출물을 임의로 완결·확정하지 않음.

---

## §4 사람·AI 역할

| 주체 | 수행 역할 |
|---|---|
| **사람** | 초기 Need(필요성·배경·핵심 기능) 제공, 결과물 형태·구조 지정, 권장안 중 의사결정, 검토·수정 지시, 최종 승인 |
| **AI** | 양식 구조로 초안 작성, 도출 가능한 요구 정리, 공백은 권장안·예시로 의사결정 요청, 결정 반영·구체화, 상태 기록 |

- 판단 경계: **Human in the loop** — 사람이 방향·기준·승인을 보유, AI가 작성을 실행.

## §5 최초 지시문 작성법 (사람용)

시드 입력(대상·배경/필요성)만 담고, 절차·산출물은 가이드·양식을 참조로 지정해 짧게 작성. 세부는 이후
회차에서 구체화.

**포함 요소**

| 요소 | 작성 내용 |
|---|---|
| 대상 | 만들려는 시스템·핵심 목적 한두 줄 |
| 배경/필요성 | 현재 불편·문제, 필요를 느낀 이유 |
| 진행 방식 | 이 가이드(`docs/[요구분석]_요구사항분석_가이드.md`) 절차 참조 |
| 산출물 | `docs/[요구분석]_요구사항정의서.md` 양식으로 초안 요청 |

**지시문 서식**

협업 규칙(임의 확정 금지·권장안·점진적 구체화)은 이 가이드가 담으므로, 지시문은 **시드 입력만
구조화**하고 가이드·양식을 참조로 지정. 필드형으로 작성.

```text
[요구분석] <시스템명>

- 대상: <만들려는 시스템·핵심 목적>
- 배경/필요성: <현재 불편·문제, 필요를 느낀 이유>
- 진행 방식: `.idea\[요구분석]_요구사항분석_가이드.md` 절차에 따라 진행
- 산출물: `.idea\[요구분석]_요구사항정의서.md` 양식으로 초안 작성
```

**예시 (회의록 관리시스템)**

```text
[요구분석] 회의록 관리시스템

- 대상: 회의 일정을 등록하고, 등록된 일정에 따라 회의록을 기록·관리하는 시스템
- 배경/필요성: 현재 회의록을 파일로 관리 → 이력 추적·회의 결과 반영이 누락되는 경우가 많음
              (회의록을 아예 쓰지 않는 경우도 있음)
- 진행 방식: `.idea\[요구분석]_요구사항분석_가이드.md` 절차에 따라 진행
- 산출물: `.idea\[요구분석]_요구사항정의서.md` 양식으로 초안 작성
```

## §6 AI 작성 규칙 (AI용)

**작성 순서**

1. 지시문의 Need에서 직접 도출 가능한 요구만 양식 구조(§7)에 채움.
2. Input 밖 항목은 확정하지 않음 → 의사결정 요청 목록으로 분리.
3. 불가피한 임시값은 `(가정)` 표기, 승인 전까지 확정 아님으로 취급.
4. 인수조건(AC)은 검증 가능한 형태로 작성.
5. 1차 초안 + 의사결정 요청까지 제시, 사람 결정 후 다음 회차에서 구체화.

**의사결정 요청 서식**

각 미결 항목을 아래 형태로 제시, 사람이 고르거나 지시하도록 함.

```text
[의사결정 요청] <항목명>
- 현황: <Input 유무·부족한 이유>
- 권장안: <권장 방향 1순위>
- 예시(선택지): A) <...>  B) <...>  C) <...>
- 요청: 위 중 선택 또는 다른 방향 지시 요청
```

- 설계(How)로 넘어가는 항목은 요구 수준으로 되돌리거나, 설계 단계 이관 대상으로 표시.

## §8 제약사항

필수 준수 항목.

- 요구(What) 수준 유지 — 설계(How) 항목은 IA·설계 단계로 이관.
- 자료 부족 지점은 권장안·예시로 의사결정 요청 후 반영.
- 인수조건(AC)은 검증 가능한 형태로 작성.
- 산출물 확정은 사람 승인으로 처리.
